# Видеовложение в существующем Spring + React приложении

[← Руководства](../README.md) · [English](../en/integration.md) · [API](reference.md)

Клиент прикладывает видео к обращению в поддержку. Браузер передаёт исходник потоком в хранилище, сервер готовит HLS-сегменты для перемотки, плеер получает начало до нажатия Play. Обращение, вход и права на вложение остаются ответственностью приложения.

## Структура проекта

```text
server/
  build.gradle.kts
  src/main/resources/application.yml
  src/main/java/.../VideoController.java
ui/
  package.json
  src/VideoMessage.tsx
```

В [полном защищённом Spring-примере](https://github.com/dlorian59/video-streams-spring-boot-starter/tree/main/examples/secured-video) находятся согласованные dependency, конфигурация и controller. Маршруты приложения подключаются явно, стартер не открывает их автоматически. Минимальная Java — 17; FFmpeg и ffprobe устанавливаются отдельно.

Зависимости UI перечислены в [README](../../README.md). Один раз подключите stylesheet. [Полный компонент VideoMessage](../../examples/spring-react/VideoMessage.tsx) содержит импорты и комментарии на двух языках:

```tsx
const key = `${account.id}:${attachmentId}`;
<VideoAttachment
  scope={account.id}
  objectKey={key}
  objectsUrl="/api/video-sources"
  prepareUrl={`/api/videos/${encodeURIComponent(key)}/prepare`}
  headers={{ [account.csrfHeader]: account.csrfToken }}
  language="ru"
  onPrepared={saveVideoReference}
/>;
```

Сервер сверяет префикс `account.id` с авторизованным Principal. Префикс из браузера сам по себе не даёт прав. `attachmentId` остаётся постоянным в течение загрузки; для другого исходника создавайте новый идентификатор. При смене аккаунта меняйте `scope` сразу, без transition и отложенных обновлений.

## Сквозной поток

| Этап | Запрос | Подтверждённый результат |
|---|---|---|
| Загрузка исходника | Raw `PUT /api/video-sources/{encodedKey}`, `X-Upload-Length` | `201 {committed:true,key,bytes,etag}`; file-streams проверяет commit. |
| Подготовка | `POST /api/videos/{encodedKey}/prepare`, JSON `{sourceKey:key}` | Один запрос ждёт `201 {status:"ready",generation,playlistUrl,durationSeconds,segmentCount}`. |
| Просмотр | Авторизованные GET плейлиста и относительных URL init/сегментов | hls.js добавляет фрагменты в media element; следующие загружаются при просмотре или перемотке. |

Успешный PUT ещё не означает готовность видео. Подготовка читает подтверждённый исходник через file-streams, запускает FFmpeg, публикует неизменяемые артефакты, затем финальный плейлист. В V1 нет вымышленной очереди с 202, polling или базы заданий. При необходимости вызывайте тот же серверный сервис из собственной устойчивой очереди.

Фронтенд и сервер рекомендуется размещать под одним origin через существующий reverse proxy. Session cookies передаются с `same-origin`, а изменяющие PUT/POST — с CSRF-заголовком приложения. Каждый GET сегмента тоже проверяет доступ. Для разных origins нужны явно настроенный клиент, CORS и совместимые credentials; bearer token в URL плейлиста не добавляется.

## Исходники и ограничения

Picker предлагает MP4/MOV/WebM/Matroska. `accept` — подсказка при выборе, а не проверка содержимого; исходник проверяет сервер. Профиль вложения по умолчанию — `media` (512 MiB), что совпадает с серверным лимитом входа. Нужно также настроить ограничения deployment, место на диске и доступность FFmpeg.

Клиент принимает незашифрованные fMP4 HLS VOD media playlists. Цель preview — четыре секунды, просмотра — двенадцать впереди и восемь позади. Ограничиваются отдельные ответы: 1 MiB плейлист и 16 MiB фрагмент. Это не жёсткий предел всей памяти процесса. Неподдерживаемый MSE/codec и ошибка декодирования показываются явно; fallback на целый Blob отсутствует.

## Ошибки и восстановление

- **Ошибка загрузки исходника:** file-streams сохраняет подтверждённый или неизвестный результат. Для неизвестного исходника нужен существующий `reconcileUpload` приложения перед повтором.
- **Подготовка отклонена:** отдельные однозначные статусы отказа разрешают кнопку «Повторить подготовку». Автоматического повтора нет.
- **Потерян ответ, истекло время или отменено ожидание:** исходник сохранён, готовая generation может существовать. Компонент показывает неизвестный результат и не повторяет POST. HTTP 408 тоже считается неизвестным.
- **Приложение выяснило неизвестный результат:** передайте подтверждённый `existingVideo`. У библиотеки нет job store, она не может сама восстановить generation, ответ о которой потерян. Для устойчивого восстановления приложение сохраняет метаданные на сервере.
- **Ошибка GET/декодирования:** «Повторить воспроизведение» создаёт новую сессию. Исходник и FFmpeg-подготовка не повторяются.

`onPrepared` передаёт метаданные приложению, но не сохраняет их надёжно на сервере. `existingVideo` открывает ранее разрешённую ссылку; `existingFile` может описывать сохранённый исходник. После подтверждения `VideoAttachment` блокирует замену исходника внутри этого компонента; для следующей загрузки нужен новый attachment ID.
